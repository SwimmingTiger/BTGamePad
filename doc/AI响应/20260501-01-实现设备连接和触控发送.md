## Plan: 蓝牙 HID 虚拟摇杆

目标已经收敛：本机鸿蒙手机作为蓝牙 HID 外设，连接另一台鸿蒙手机，把本机 gamepad 左摇杆转换成远程游戏左下角虚拟摇杆拖动。主路径优先用“蓝牙鼠标/触控板式相对指针”打通最小闭环；如果远程游戏不接受这类指针事件，再切到“digitizer/touch 式绝对坐标 HID”保底分支。DevEco Studio 下的 SDK 已定位到 C:\Program Files\Huawei\DevEco Studio\sdk\default\openharmony，当前工程 targetSdkVersion 也是 23，和 HID Device API 的版本门槛对齐。

**Steps**
1. 固定平台前提：确认测试机支持经典蓝牙外设模式，应用保持前台运行，系统里没有别的应用占用 HID Device 注册。
2. 先把工程拆成四层：手柄输入采集、摇杆归一化与状态机、HID 会话层、配置/校准 UI。第一阶段只做左摇杆，不混入按钮和右摇杆。
3. 实现主路径 HID 模型：注册一个鼠标/触控板式 HID Device，自定义 report descriptor，至少包含按钮位和相对 X/Y 轴，并建立稳定的 sendReport 节流机制。
4. 做左摇杆三态状态机：离开死区时开始“按下”，持续偏移时连续“拖动”，回到死区时“松开”。这里要加死区、回中滞后、最大速度和曲线映射，避免抖动断触。
5. 加一个远程摇杆校准页：记录左下角虚拟摇杆中心区和有效半径。主路径虽然是相对指针，但标定数据仍然用于控制初始定位、拖动幅度和回中策略。
6. 做蓝牙会话流程：配对选择、HID 注册、连接、断线重连、前后台切换、异常提示。重点处理前台注册和生命周期释放。
7. 加可观测性：显示 gamepad 原始值、归一化后的摇杆值、最近一次 HID report、注册状态、连接状态和发送时间，便于快速区分输入层、链路层和远程兼容性问题。
8. 保留保底分支：如果远程鸿蒙系统只把主路径识别成普通指针，进游戏后无法拖动左下角摇杆，就改用 digitizer/tablet 或 touch 类 descriptor，发送绝对坐标按下/拖动/松开。这个分支复用前面的状态机和标定，只替换 descriptor 与报告打包逻辑。
9. 第一阶段完成标准：左摇杆推动角色稳定移动，回中即停止；暂不扩展右摇杆、技能键、宏和手势。
