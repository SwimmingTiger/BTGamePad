### 核心设计

| 层 | 技术 | 说明 |
|---|---|---|
| **原生监听** | `OH_Input_AddMouseEventMonitor` via NAPI | C 层注册全局鼠标回调，通过 `napi_threadsafe_function` 回传坐标 |
| **ETS 层** | `@ohos.net.socket` UDPSocket | 定时从缓存读坐标，拼 8 字节 LE 包发送 |
| **UI** | ArkUI 声明式 | IP/端口输入、频率滑块、实时坐标显示、状态指示灯 |
| **权限** | `INPUT_MONITORING` + `INTERNET` | module.json5 声明，首次运行弹窗授权 |

### 与 CLI 版的关键区别

CLI 以 shell 用户运行，无 Android/HarmonyOS 权限模型，`OH_Input_AddMouseEventMonitor` 直接返回 `INPUT_PERMISSION_DENIED`。HAP 通过标准权限声明机制，在开发者模式下可正常获取 `INPUT_MONITORING` 权限。

## 新算法设计

纯事件驱动，无定时器：

```
帧循环 (由手柄输入事件驱动):
  reconcileExecutionOutput()
    → tickMouseApproach(target)
        ├─ 未校准: 按初始猜测比发送小步 delta
        │           设置 mouseAfterCalSent=true, 记录发送量
        └─ 已校准: 用 mouseCalRatioX/Y 计算精准 delta

反馈到达 (UDP 消息回调):
  applyMouseFeedbackPosition()
    ├─ 检测 mouseAfterCalSent → 计算真实移动量
    ├─ 更新校准比: ratioX = 移动量 / 发送量
    └─ mouseCalibrated = true

下一帧:
  tickMouseApproach() 现在用精准比计算 delta
  → 重复直到 distance < 15 → 返回 arrived
  → 按钮: arrived → 点击
  → 摇杆: at center → 沿方向发送增量
```

**关键点**：首次移动时无反馈 → 不校准、不发后续 → 鼠标不会乱动。反馈到达后立即校准 → 后续移动精准。目标变化时重置校准 → 从头适应当前设备灵敏度。
