**Root cause analysis:**

In `normalizeControlGeometry`, when the app starts, background image metrics aren't loaded yet (`hasBackgroundImageMetrics()` returns false), so `getBackgroundWidthToHeightRatio()` returns 1. For round controls (摇杆移动, 按钮), the code does:

1. `nextSize = max(width, height / 1)` → forces width = max(width, height)
2. `height = size * 1` → forces height = width

This destroys the stored aspect ratio. Later when background metrics load, `refreshRoundControlGeometryForCurrentBackground` adjusts height = width × ratio, making controls taller. If this gets persisted, the next restart the cycle repeats cumulatively.

**Fix:** When background metrics are not available, clamp width and height independently for round controls — don't force them to be equal.

## 修复完成

### 问题根因

`normalizeControlGeometry` 方法中，圆形控件（摇杆移动、按钮等）通过 `toRoundControlWidthUnits` / `toRoundControlHeightUnits` 在 width 和 height 之间互相换算，这两个方法依赖 `getBackgroundWidthToHeightRatio()`（背景图的宽高比）。

每次 app 重新打开的启动流程是：
1. **加载布局** → 此时背景图尺寸尚未读取 → `ratio` 回退为 `1`
2. 对圆形控件：`width = height = max(width, height)` → **宽度被强制拉大到与高度相等**
3. **背景图加载完成** → `ratio` 恢复为正确值（如 1.5）
4. `refreshRoundControlGeometryForCurrentBackground` 调用 → `height = width × ratio` → **高度进一步变大**
5. 用户操作触发保存 → 变大的尺寸被持久化
6. **下次重启** → 回到步骤 1，循环累积

### 修复方案

在 `normalizeControlGeometry` 中，当背景图尺寸尚未就绪时（`hasBackgroundImageMetrics() === false`），对圆形控件**独立钳位 width 和 height**，不再互相强制换算，从而保留已存储的正确尺寸。

```typescript
// 修复前：无论背景是否就绪，都强制 width/height 互相换算

    const nextSize = Math.max(normalizedControl.width, 
        this.toRoundControlWidthUnits(normalizedControl.height));  // ratio=1 时 height→width 无转换
    normalizedControl.width = size;
    normalizedControl.height = this.toRoundControlHeightUnits(size); // ratio=1 时 width→height 不保持比例
}
```
